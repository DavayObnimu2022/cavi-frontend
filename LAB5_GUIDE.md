# Лабораторная 5 — разбор решения

Документ для тебя: что сделано, в каком порядке и почему именно так. Проект уже приведён к React + TypeScript, собирается, проходит `typecheck` и `lint`.

## 1. Что требовалось

- SPA на React + TypeScript.
- Три страницы: лента, добавление, плитка.
- Нижний navbar из 4 пунктов: лента, добавление, плитка, вход.
- Доступны только два пункта: лента и плитка.
- Данные карточек — только из mock-коллекции, без бэкенда.
- Изображение и видео по умолчанию, если поле пустое.
- Фильтр на странице плитки.
- Компоненты React-Bootstrap.
- Никакого Redux и Context.
- README с описанием страниц, кнопок и полей.

## 2. Почему выбран именно такой каркас

Приложение сделано как мобильный экран внутри браузера: контейнер `.phone`, статус-бар, контентная область и нижняя навигация. Это повторяет дизайн из `docx` и удобно для скриншотов.

Маршруты:

- `/feed` — лента;
- `/grid` — плитка;
- `/add` — добавление;
- `/` и неизвестные адреса перенаправляются на `/feed`.

Роутер подключён в `src/main.tsx` через `BrowserRouter`, а сами маршруты описаны в `src/App.tsx`. Так навигация не перезагружает страницу, и приложение остаётся SPA.

## 5. Mock-коллекция

Данные лежат в `src/collections/services.ts`. Это обычный TypeScript-массив объектов, без запросов к серверу.

```ts
export interface Service {
  id: string
  title: string
  description: string
  category: string
  price: number
  date: string
  age?: number
  pressure?: number
  likes: number
  imageUrl?: string
  videoUrl?: string
}
```

В коллекции 6 услуг. У всех услуг поля `imageUrl` и `videoUrl` пустые — это специально, чтобы везде показывались фото и видео по умолчанию.

Почему так: по заданию содержимое карточек берётся только из mock-коллекции. Никаких `fetch`, `axios`, Redux и Context нет.

## 6. Медиа по умолчанию

Файлы:

- `src/assets/default-image.svg` — единое изображение по умолчанию;
- `src/assets/default-video.mp4` — единое видео по умолчанию.

Других изображений и видео в проекте нет: у всех mock-услуг поля `imageUrl` и `videoUrl` пустые, поэтому везде показывается одно и то же фото и одно и то же видео.

Логика в `src/components/ServiceMedia.tsx`:

```tsx
const [imageSrc, setImageSrc] = useState(imageUrl || defaultImage)
const [videoSrc, setVideoSrc] = useState(videoUrl || defaultVideo)
```

Если поле пустое (`''`, `undefined`), сразу подставляется локальный файл. Если URL есть, но файл не загрузился, срабатывает `onError` и тоже подставляется локальный файл:

```tsx
onError={() => setImageSrc(defaultImage)}
```

Для видео аналогично:

```tsx
onError={() => setVideoSrc(defaultVideo)}
```

В ленте видео используется как фон, а изображение — как `poster`. В плитке показывается изображение.

## 8. Страница «Лента»

Файл: `src/pages/FeedPage.tsx`.

Что делает страница:

- берёт услугу из mock-коллекции;
- хранит смещение по списку услуг;
- при нажатии на стрелку переходит к следующей услуге;
- хранит лайки по `id` услуги;
- читает параметр `?service=...` из URL, чтобы открыть конкретную услугу из плитки.

Ключевая логика:

```tsx
const baseIndex = findServiceIndex(feedState.requestedId)
const currentIndex =
  services.length === 0 ? 0 : (baseIndex + feedState.offset) % services.length
```

Почему так: если пользователь открыл услугу из плитки, `baseIndex` задаёт начальную позицию. Кнопка «дальше» увеличивает `offset`, а `% services.length` зацикливает ленту.

Компонент `src/components/FeedCard.tsx` отвечает только за отображение:

- видео/изображение;
- бейджи возраста и давления;
- кнопку лайка;
- кнопку следующей услуги;
- название, описание и ссылку «Ещё».

Он не знает, откуда взялись данные. Всё приходит через props.

## 9. Страница «Плитка» и фильтр

Файл: `src/pages/GridPage.tsx`.

Состояния:

- `filter` — черновик фильтра, который меняется при вводе;
- `appliedFilter` — фильтр, который реально применён к списку.

Почему два состояния: пока пользователь двигает ползунки, список не должен дёргаться на каждом пикселе. Список меняется только по кнопке «Применить».

Фильтрация по возрасту:

```tsx
const filteredServices = useMemo(() => {
  return services.filter((service) => {
    const age = service.age ?? 0
    return age >= appliedFilter.minAge && age <= appliedFilter.maxAge
  })
}, [appliedFilter])
```

`useMemo` нужен, чтобы не пересчитывать фильтр на каждом рендере, если `appliedFilter` не менялся.

Компонент фильтра: `src/components/ServiceFilter.tsx`. Он управляемый и получает props:

```ts
interface ServiceFilterProps {
  values: ServiceFilterValues
  onChange: (values: ServiceFilterValues) => void
  onApply: () => void
}
```

- `values` — текущие значения `{ minAge, maxAge }`;
- `onChange` — обновить черновик;
- `onApply` — применить.

Внутри используются React-Bootstrap `Form`, `Form.Range` и `Button`.

Карточка плитки — `src/components/ServiceCard.tsx`. Она использует `Card` из React-Bootstrap и `Link` из React Router. Нажатие на карточку открывает `/feed?service=<id>`.

## 12. Какие хуки используются и зачем

### `useState`

- `FeedPage`: состояние ленты и лайков.
- `GridPage`: черновик фильтра и применённый фильтр.
- `ServiceMedia`: текущий источник изображения и видео (нужен для `onError`).

### `useEffect`

- `FeedPage`: обновляет `document.title` при смене услуги. Это работа с внешней системой (заголовок вкладки браузера), поэтому эффект уместен.

### `useMemo`

- `GridPage`: кэширует результат фильтрации, пока не изменился `appliedFilter`.

### `useSearchParams`

- `FeedPage`: читает `?service=...`, чтобы открыть услугу, выбранную в плитке.

Больше хуков нет. Redux, Context, `useContext`, `useReducer` не используются.

## 13. Ответы на контрольные вопросы

### React

React — библиотека для построения пользовательских интерфейсов. Она позволяет описывать UI декларативно через компоненты, хранить состояние и автоматически обновлять DOM при его изменении. React работает с виртуальным DOM: сначала строит виртуальное дерево, сравнивает его с предыдущим и вносит минимальные изменения в реальный DOM.

### Props и состояние

`props` — входные данные компонента. Они передаются от родителя к ребёнку и внутри компонента не изменяются. `state` — внутренние данные компонента, которые могут меняться. Изменение состояния запускает повторный рендер. Проще говоря: props нужны, чтобы получать информацию, state — чтобы управлять компонентом.

### Компонент и элемент

Компонент — это функция (или класс), которая принимает props и возвращает JSX. Элемент — это простой объект, описывающий, что должно быть отрисовано. JSX-тег `<FeedCard service={...} />` — это элемент, а `FeedCard` — компонент.

### useState и useEffect

`useState` создаёт состояние и функцию для его изменения:

```tsx
const [liked, setLiked] = useState(false)
```

`useEffect` выполняет побочные эффекты после рендера: работу с DOM, подписки, запросы к API. Второй аргумент — массив зависимостей. Если он пустой, эффект выполнится один раз после монтирования. Если в массиве есть значения, эффект повторится при их изменении.

Важно: `useEffect` — не весь жизненный цикл, а только три события: монтирование, обновление и размонтирование.

### Жизненный цикл компонента

- Монтирование — компонент впервые появляется в DOM.
- Обновление — меняются props или state, компонент рендерится заново.
- Размонтирование — компонент удаляется из DOM.

В функциональных компонентах аналогами методов жизненного цикла являются хуки. `useEffect` с пустым массивом зависимостей заменяет `componentDidMount`, с зависимостями — `componentDidUpdate`, а возвращаемая функция очистки — `componentWillUnmount`.

### Vite и Babel

Vite — окружение разработки и сборщик. Он быстро запускает dev-сервер, поддерживает ES-модули и горячую замену модулей (HMR), а для production-сборки использует Rollup. Babel — транспайлер, который преобразует современный JavaScript (ES6+) и JSX в код, понятный старым браузерам. В проекте Vite отвечает за разработку и сборку, а JSX/TSX преобразуется плагином React.

## 15. Что сказать на защите

- Приложение — SPA на React + TypeScript, роутинг через React Router.
- Данные берутся из mock-коллекции `src/collections/services.ts`, бэкенд не используется.

- Используются только `useState`, `useEffect`, `useMemo` и `useSearchParams`.
- Проект проходит `npm run typecheck`, `npm run lint`, `npm run build`.
