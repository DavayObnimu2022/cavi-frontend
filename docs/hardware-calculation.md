# Расчёт аппаратных требований

## 1. Исходные данные

- Зарегистрированных пользователей: **100 000**.
- Доля активных пользователей в день: **10 %**, то есть **10 000** активных пользователей.
- Количество услуг, которые просматривает один активный пользователь за день: **20**.
- HTTP-запросов на одну услугу: **6**:
  1. `GET /api/services/{id}` — карточка услуги;
  2. `GET /api/services/{id}/media/image` — изображение;
  3. `GET /api/services/{id}/media/video` — видео;
  4. `GET /api/services/{id}/likes` — счётчик лайков;
  5. `GET /api/services/{id}/reviews` — отзывы;
  6. `GET /api/services/{id}/similar` — похожие услуги.
- Рабочее время пользователей: **8 ч = 28 800 с**.
- Коэффициент пиковой нагрузки: **3**.
- Производительность сервера приложения: **50 RPS на 1 ядро**.
- Оперативная память: **4 ГБ на 1 ядро**.
- Медиафайлы отдаются из S3, поэтому из 6 запросов к API приложения относятся 4, а 2 — к S3.

## 2. Расчёт RPS

Суммарное число HTTP-запросов в день:

```text
N_день = 10 000 × 20 × 6 = 1 200 000 запросов/день
```

Средний RPS:

```text
RPS_сред = 1 200 000 / 28 800 = 41,67 RPS
```

Пиковый RPS:

```text
RPS_пик = 41,67 × 3 = 125,00 RPS
```

Пиковый RPS на API приложения (4 из 6 запросов):

```text
RPS_пик_API = 125,00 × 4 / 6 = 83,33 RPS
```

## 3. Расчёт ядер и оперативной памяти

С учётом запаса 30 %:

```text
N_ядер = ceil(83,33 / 50 × 1,3) = ceil(2,17) = 3 ядра
```

```text
RAM = 3 × 4 ГБ = 12 ГБ
```

Итог для сервера приложения:

| Параметр | Значение |
|---|---:|
| Ядра | 3 |
| Оперативная память | 12 ГБ |
| Пиковый RPS API | 83,33 |
| Пиковый RPS S3 | 41,67 |

## 5. Прирост БД за 5 лет

- Услуги: `100 000 + 20 000 × 5 = 200 000` записей.
- Пользователи: `100 000 + 20 000 × 5 = 200 000` записей.
- Лайки: `200 000 × 20 = 4 000 000` записей.
- Отзывы: `200 000 × 2 = 400 000` записей.
- Категории: `50` записей.

```text
services   = 200 000 × 2 902 = 580 400 000 байт = 580,40 МБ
users      = 200 000 × 725   = 145 000 000 байт = 145,00 МБ
likes      = 4 000 000 × 67,2 = 268 800 000 байт = 268,80 МБ
reviews    = 400 000 × 1 270 = 508 000 000 байт = 508,00 МБ
categories = 50 × 739        = 36 950 байт     = 0,04 МБ
```

```text
Итого данные = 580,40 + 145,00 + 268,80 + 508,00 + 0,04 = 1 502,24 МБ
Индексы (+30 %) = 1 502,24 × 1,3 = 1 952,91 МБ
WAL и резервные копии (+50 %) = 1 952,91 × 1,5 = 2 929,36 МБ ≈ 2,93 ГБ
```

С учётом ОС и логов:

```text
Диск БД = 2,93 ГБ + 20 ГБ = 22,93 ГБ ≈ 50 ГБ с запасом
```

## 6. Размер объектов в S3

- Изображение одной услуги: **300 КБ = 0,3 МБ**.
- Видео одной услуги: **8 МБ**.
- Итого на одну услугу: `0,3 + 8 = 8,3 МБ`.

```text
S3 = 200 000 × 8,3 МБ = 1 660 000 МБ = 1 660 ГБ = 1,66 ТБ
С учётом версий и миниатюр (+20 %) = 1,66 × 1,2 = 1,99 ТБ ≈ 2,1 ТБ
```
